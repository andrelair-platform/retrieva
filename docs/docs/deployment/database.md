# Database Operations

Operational notes for the **PostgreSQL + Drizzle** layer: transactions, migrations, indexes,
connection pooling, and local-dev notes. (The app migrated off MongoDB — RTV-45..49.)

## Transactions

PostgreSQL supports multi-statement transactions on a **single node** — no replica set required
(unlike the former MongoDB setup). Transactional flows:

- `services/AssessmentService` — risk decision (assessment update + workspace update, atomic)
- `services/rag` — conversation / message persistence

They can be exercised against a plain local Postgres (`docker compose up -d postgres`), including in
CI with a single container — no special topology needed.

## Migrations (Drizzle)

Schema/data changes go through **Drizzle migrations** (`db/migrations/`, generated by `drizzle-kit`),
not ad-hoc scripts. Pending migrations are **applied automatically on boot** (`runMigrations()` in
`index.ts`, idempotent), so a fresh database is ready after the first start.

```bash
npm run db:generate      # generate SQL from the Drizzle schema changes (db/schema/*.ts)
npm run db:migrate       # apply pending migrations (also runs automatically on boot)
npm run db:studio        # drizzle-kit studio (inspect the DB)
```

Migrations are **idempotent** and committed to the repo (reviewable SQL — part of the cert
defensibility evidence).

## Indexes

Indexes are declared in the **Drizzle schema** (`db/schema/*.ts`) and created by migrations — no
runtime `autoIndex` step. NoSQL-injection concerns no longer apply (parameterised SQL via Drizzle);
request-level input sanitisation still lives in `middleware/securitySanitizer.ts`, and tenant scoping
is enforced by `entityScopeCondition` (see [multi-tenancy](../architecture/multi-tenancy)).

## Connection pooling

`config/db.ts` opens a `pg` Pool from `DATABASE_URL`:

- `max: PG_POOL_MAX ?? 50`, `min: PG_POOL_MIN ?? 10`
- the pool is created lazily and cached; `connectPg()` runs `SELECT 1` at boot to fail fast if the DB
  is unreachable.

## Local development

A single Postgres container is all you need:

```bash
docker compose up -d postgres            # from the retrieva repo
# DATABASE_URL=postgres://retrieva:retrieva@localhost:5432/retrieva
```

The backend applies migrations on boot, so the schema is created automatically on first run — no
manual migrate step required for a fresh local database.
